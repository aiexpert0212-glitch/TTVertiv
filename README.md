# Vertiv 제품 선정 · 경쟁사 비교 지원 시스템 (프로토타입)

고객 요구사항을 분석해 최적의 Vertiv 구성을 추천하고, 경쟁사 제품과 사양·효율·TCO를 비교해 강점과 영업 메시지를 만들어 줍니다.

## 실행

```bash
node server.js
```

브라우저에서 http://localhost:3000 을 엽니다. 서버 없이 `index.html`을 직접 열어도 동작합니다(이때 AI 키는 브라우저에 저장).

### Claude AI 연결 (선택)
1. `.env.example` 을 `.env` 로 복사합니다.
2. `ANTHROPIC_API_KEY=` 뒤에 키를 넣습니다.
3. 서버를 재시작합니다.

키가 없으면 **데모 모드**(규칙 기반 분석·메시지)로 모든 기능이 동작합니다.

## 화면 흐름
1. **요구사항**: RFP 텍스트 붙여넣기 → AI 분석 → 폼 자동 입력 (수동 수정 가능)
2. **추천 결과**: 제품군별 Vertiv 추천 구성, 점수, 근거, 전체 후보 순위
3. **경쟁사 비교**: 레이더 차트, TCO 막대, 비교표, 경쟁사별 강점·약점, 영업 메시지 생성
4. **제안 리포트**: 인쇄 / PDF 저장
5. **저장된 비교**: 결과·비교 화면 상단에서 저장 → 목록에서 검색, 다시 열기, 개별/선택 삭제
6. **제품 DB**: 샘플 제품 조회

### 저장 위치
- **Supabase**: `.env`에 `SUPABASE_URL`과 `SUPABASE_KEY`가 있으면 Supabase(PostgreSQL)에 저장합니다.
  1. Supabase 대시보드 → **SQL Editor**에서 [`supabase/schema.sql`](supabase/schema.sql)을 실행해 테이블과 접근 정책을 만듭니다.
  2. **Project Settings → API Keys**의 키를 `.env`의 `SUPABASE_KEY=` 뒤에 넣습니다. (예전 이름 `SUPABASE_SECRET_KEY`도 인식)
  3. 서버를 재시작하면 로그에 `저장소: Supabase`가 표시됩니다.
  - 현재는 **publishable 키 + anon 정책** 방식입니다. 프로젝트 주소와 키를 아는 사람은 누구나 저장된 비교를 읽고 삭제할 수 있으므로 **샘플 데이터 테스트용**입니다. 실제 가격·고객 정보를 넣기 전에는 secret 키(서버 전용)로 바꾸고 `schema.sql`의 anon 정책을 제거하거나, 로그인 기반 정책을 도입하세요.
- **SQLite**: Supabase 설정이 없으면 서버 로컬 DB(`data/vss.db`)에 저장합니다. 백업은 이 파일을 복사하면 됩니다.
- `index.html`을 직접 열면 브라우저(localStorage)에만 저장됩니다.
- 저장 시 비교 결과 전체를 스냅샷으로 보관하므로, 이후 제품 DB가 바뀌어도 저장 당시 결과 그대로 다시 볼 수 있습니다.

## 브랜딩 (회사 로고)
- `assets/logo-unipoint.png`(또는 `.svg`/`.jpg`)를 넣으면 상단바·홈·제안 리포트·푸터에 자동 표시됩니다. 없으면 텍스트 워드마크가 표시됩니다.
- Vertiv 로고는 `assets/logo-vertiv.png`(선택).

## 구조
| 파일 | 역할 |
|---|---|
| `js/brand.js` | 회사명·제품명·로고 설정 |
| `assets/` | 로고 파일 위치 |
| `js/data.js` | 제품·경쟁사 샘플 DB (사양 근사치, **가격은 가상값**) |
| `js/engine.js` | 용량 산정, 점수화, 경쟁사 비교, 강점 도출 |
| `js/ai.js` | Claude API 호출(요구사항 추출, 영업 메시지) + 규칙 기반 대체 |
| `js/storage.js` | 저장된 비교 저장소 (서버 DB / 브라우저 자동 선택) |
| `js/app.js` | 화면 · 라우팅 |
| `server.js` | 정적 파일 + 저장 비교 API(SQLite) + Claude API 프록시 (외부 패키지 없음) |

## 선정 로직 요약
- **UPS**: 설계용량 = IT 부하 × (1+증설%) ÷ 최대부하율. 모듈형은 모듈 N+1, 단일기는 병렬 N+1, 2N은 2계통. 부하율에 따른 효율 저하를 반영하고, 손실전력은 냉방 부하(×1.3)까지 포함합니다.
- **정밀공조**: 설계 열부하 = IT 부하 × (1+증설%) × 1.1. 이중화를 반영해 대수를 산정하고, 이코노마이저 절감률을 반영한 연간 실효 EER로 비교합니다. CW 방식은 칠러 전력(COP 4.5)을 포함합니다.
- **PDU**: 랙당 부하를 80% 디레이팅한 정격으로 선정하고, A/B 피드 기준 2대/랙.
- **점수**: 지표별 상대 점수(최고 제품 = 100)를 고객 우선순위별 가중치로 평균합니다.
- **TCO** = 초기 투자비 + 기간 내 전력비 + 유지보수비(연 3%).

> 실제 제안에 쓰려면 `js/data.js`의 사양과 가격을 사내 데이터시트·견적 기준으로 교체하세요.
